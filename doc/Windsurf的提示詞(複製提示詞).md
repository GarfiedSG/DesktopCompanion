# 給 Windsurf 的提示詞指南

這份文件不是給 Windsurf 讀的，是給你自己複製提示詞用的。
每次只複製一個步驟的提示詞到 Windsurf 的 Cascade 對話框，完成後再進行下一步。

---

## 一、使用前準備

### 1.1 專案目錄檢查

確認以下結構已就位：

```text
桌面伴侶/
├─ .windsurfrules
├─ docs/
│  ├─ 需求文檔.md
│  ├─ step1_骨架與窗口.md
│  ├─ step2_動畫與行為.md
│  ├─ step3_設置與聲音.md
│  ├─ step4_服務擴展.md
│  ├─ step5_優化打包.md
│  └─ 給Windsurf的提示詞.md
├─ 文檔/
│  └─ 晴兒.png
└─ （其餘檔案由 Windsurf 按步驟生成）
```

### 1.2 安裝依賴

在專案目錄開啟終端，執行：

```bash
pip install PySide6 edge-tts pillow
```

### 1.3 開啟 Windsurf

1. 用 Windsurf 打開「桌面伴侶」資料夾。
2. 確認 `.windsurfrules` 已被讀取（可在 Cascade 中問「你讀到了什麼規則？」驗證）。
3. 確認 `docs/` 下的文件都可見。
4. 安裝繁體中文語言包（可選）：
   - 擴展市場搜尋 `Chinese`，安裝 Microsoft 官方語言包。
   - 重啟後介面變中文。

### 1.4 設定 Cascade 回覆語言

在 Cascade 對話框輸入一次：

```text
請用繁體中文回覆我所有問題，並遵循 .windsurfrules 的規則。
```

## 二、第 1 步提示詞

### 2.1 啟動第 1 步

複製以下內容到 Cascade：

```text
請閱讀 docs/需求文檔.md 和 docs/step1_骨架與窗口.md。

現在只實現第 1 步：項目骨架 + 透明置頂窗口 + 托盤 + 配置。

要求：
- 建立 step1 文件中列出的所有檔案與資料夾。
- 實現透明置頂窗口，載入 文檔/晴兒.png。
- 實現左鍵拖拽、右鍵選單、系統托盤。
- 實現 ConfigManager，用 JSON 保存位置、縮放、透明度、置頂、鎖定。
- 完成後列出修改的檔案與如何驗收。
```

### 2.2 驗收第 1 步

Windsurf 完成後，自己執行：

```bash
python main.py
```

逐項檢查 `docs/step1_骨架與窗口.md` 的「六、驗收標準」：

- [ ] 晴兒顯示正常，背景透明
- [ ] 永遠置頂
- [ ] 不顯示在工作列
- [ ] 左鍵拖拽跟手
- [ ] 右鍵選單可用
- [ ] 托盤圖示顯示
- [ ] 關閉再開位置保留
- [ ] `config.json` 正確寫入

### 2.3 有問題時

若某項不通過，複製具體問題給 Cascade：

```text
第 1 步驗收發現問題：
[描述具體現象]
預期：[描述預期行為]
請修復，只改動相關檔案。
```

### 2.4 完成第 1 步

驗收全部通過後：

```bash
git add .
git commit -m "step1: 項目骨架 + 透明置頂窗口 + 托盤 + 配置"
```

## 七、通用提示詞

### 7.1 讓 Windsurf 解釋代碼

```text
請解釋 [檔案名] 中 [類別/函式名] 的作用與流程，用繁體中文，簡潔。
```

### 7.2 讓 Windsurf 修復 Bug

```text
發現 Bug：
- 重現步驟：[描述]
- 預期行為：[描述]
- 實際行為：[描述]
- 錯誤訊息：[貼上]

請定位問題並修復，只改動相關檔案。
```

### 7.3 讓 Windsurf 新增小功能

```text
請在 [檔案名] 中新增 [功能描述]。
要求：
- 遵循 .windsurfrules 的規則。
- 不影響現有功能。
- 只改動 [具體檔案]。
- 完成後列出修改內容。
```

### 7.4 讓 Windsurf 重構

```text
請重構 [檔案名] 中的 [類別/函式]。
目標：
- [具體目標，例如：拆分職責、減少耦合]
限制：
- 不改變外部行為。
- 不引入新依賴。
- 保持向後兼容。
完成後列出修改內容與影響範圍。
```

### 7.5 讓 Windsurf 寫測試

```text
請為 [檔案名] 中的 [類別/函式] 寫單元測試。
要求：
- 用 pytest。
- 覆蓋正常與邊界情況。
- 不依賴 GUI，用 mock。
- 測試檔案放 tests/ 目錄。
```

## 八、Cascade 對話技巧

### 8.1 一次只做一件事

不要在一條訊息中要求多個步驟。例如不要說：

```text
請完成第 1、2、3 步。
```

應該分三次發送。

### 8.2 明確指出檔案

Windsurf 有時會改錯檔案。明確說：

```text
請只修改 app/ui/pet_window.py，不要動其他檔案。
```

### 8.3 要求列出修改清單

每次完成後，要求：

```text
請列出這次修改的檔案與具體改動。
```

方便你 review 與 commit。

### 8.4 遇到重複錯誤

若 Windsurf 連續兩次修不好同一個問題：

1. 停下來，自己看一下代碼。
2. 把具體錯誤與你的判斷告訴 Windsurf。
3. 或者手動修正，不要讓 Windsurf 反覆嘗試。

### 8.5 上下文太長時

Cascade 對話太長會變慢。若感覺變慢：

1. 開新對話。
2. 在新對話中說：
   ```text
   請閱讀 docs/需求文檔.md、docs/stepN_*.md 與 .windsurfrules，我們繼續第 N 步。
   ```

### 8.6 不滿意 Windsurf 的改動

Windsurf 的修改是直接寫入檔案的。若不滿意：

1. 用 `git diff` 查看改動。
2. 用 `git checkout -- <file>` 撤銷單個檔案。
3. 或者 `git reset --hard` 撤銷全部（謹慎）。

所以**每一步 commit 一次**很重要。

## 九、常見問題處理

### 9.1 Windsurf 說找不到文件

```text
請確認專案根目錄下有 docs/ 資料夾，內含需求文檔.md 與 stepN 文件。
若沒有，請告訴我缺少哪些文件，我先補齊。
```

### 9.2 Windsurf 想加需求外的功能

```text
請不要加需求外的功能。需求文檔已凍結範圍，只實現 stepN 文件中列出的內容。
```

### 9.3 Windsurf 想引入新依賴

```text
請不要引入新依賴。可用的只有 PySide6、edge-tts、pillow 與標準庫。
```

### 9.4 Windsurf 用簡體中文

```text
請用繁體中文回覆，並用繁體中文寫代碼註釋。
```

### 9.5 Windsurf 省略代碼

```text
請寫完整代碼，不要用 ... 或 pass 佔位，不要省略任何部分。
```

### 9.6 Windsurf 一次改太多檔案

```text
請只改動 [具體檔案]，不要動其他檔案。
```

## 十、進度追蹤

### 10.1 建議的進度表

| 步驟 | 狀態 | 完成日期 | Commit |
| :--- | :--- | :--- | :--- |
| 第 1 步 | ☐ 未開始 / ☐ 進行中 / ☐ 完成 | | |
| 第 2 步 | ☐ 未開始 / ☐ 進行中 / ☐ 完成 | | |
| 第 3 步 | ☐ 未開始 / ☐ 進行中 / ☐ 完成 | | |
| 第 4 步 | ☐ 未開始 / ☐ 進行中 / ☐ 完成 | | |
| 第 5 步 | ☐ 未開始 / ☐ 進行中 / ☐ 完成 | | |

### 10.2 每步的檢查點

**第 1 步完成標誌**：晴兒出現在桌面，可拖拽、可退出、位置保留。

**第 2 步完成標誌**：晴兒會呼吸、走動、被點擊有反應、被拖拽有動畫。

**第 3 步完成標誌**：設置窗口完整，可導入動畫，聲音開關生效。

**第 4 步完成標誌**：三個擴展功能獨立可開關，各自可運行。

**第 5 步完成標誌**：可打包，可開機啟動，長時間穩定。

## 十一、最終提醒

1. **一步一 commit**，出錯可回退。
2. **一次只做一件事**，不要讓 Windsurf 連續做多步。
3. **驗收要自己跑**，不要只信 Windsurf 說「完成了」。
4. **遇到問題先看代碼**，不要盲目讓 Windsurf 反覆修。
5. **對話太長就開新對話**，附上必要上下文。
6. **保持 `docs/` 與 `.windsurfrules` 更新**，這是 Windsurf 的依據。
7. **不要提前做後續步驟**，需求已凍結，按順序來。
8. **打包前先在本機測試通過**，不要在打包後才發現問題。
